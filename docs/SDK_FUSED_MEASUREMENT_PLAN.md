## 问题与本轮证据

切换前的精确区域路径为：不可变网格 → JS逐面投影/裁剪/密度 → JS区域对象 →
区域压缩 → 再打包 → 原生影像输入/归一化/规划。它保持了正确的局部误差，
但计算、元数据及复制跨越了多次所有权边界。此前只搬投影内核，仍读取每面的
多边形并重建JS对象，完整路径反而变慢。不能继续把内核耗时等同端到端收益。

本轮新增独立实验：

```text
已选精确三角面 + 相机
  → 原生计数 → 按确定数量分配
  → 原生投影/裁剪/密度 → 原生区域压缩
  → 紧凑输出描述符 → 有界wire页 → 现有原生输入/规划
  → 与JS路线相同的计划读取
```

代码位于`tests/benchmarks/fused_measurement/`，可复现入口为
`scripts/benchmark_fused_measurement.sh`。它只读挂载源码，使用独立构建目录和
实验导出，绝不覆盖产品Wasm或更新手工服务。报告写入迁移后的测试输出挂载。
没有在线图源请求、浏览器或持续服务。

输入是三组固定网格尺度、起伏/空洞/折叠三种曲面及两种面向策略，共18组，
最大64800面。每组分别执行默认容量和扩展容量，共36例；预热后交错执行5次
两条路线，保留360条原始时间及分段成本。两条路线
使用同一Float32 XYZ/UV和索引；原生路线计入精确计数、实际分配/释放、投影、
压缩、输入/规划及最终JS结果读取。没有只比较预打包内核。

另以冻结旧压缩器对照13组包含重复、乱序、空洞、密度变化、小输入和微小面积
输出扩张的输入，检查区域
顺序/字段、局部节点SSE和完整Native切面/节点误差。少一字节的工作区拒绝、
原生输入credit少一字节拒绝且不改变所有权、Wasm内存增长及最终零裸缓冲/
零上下文也纳入实验。原生输入不足返回C ABI的RESOURCE_LIMIT(5)，与运行时
等待容量的CAPACITY_PENDING(9)不同；夹具曾混淆二者的失败日志保留。

首版为输出保留最多3N张完整168字节区域记录。面积容差可让一个组生成多于
N个扇形面，不能简单按N定价。但3N完整记录产生很大的无用预留。最终版只存
24字节描述符：原始行索引，或三个源点索引加保守密度；按最多256行物化到已定价的
单一wire页。没有量化、改变归并条件或删去区域证明。
wire容量同时受3N上界约束，小输入不必预留整个256行页。12个极小三角面
可按原面积容差生成多于12个凸包扇形面，新增对照实际触发这一边界。

证据目录为`viewer_verify_output/fused_measurement_20261019/`。
`full_row_output/`保存首版的匹配源码/Wasm和结果；`final/`是最终可复现脚本的
构建与测量结果。原型的严格有限输入对照不等于整个测量算法的通用验收。

最终控制对照保持图源最高8级和误差1.25px相同，只改变纹理/绘制配额。
默认214纹理/512附加绘制时16/18例达标；两个64800面折叠用例明确报告纹理
容量受限，误差约1.515/1.494px。扩展4096纹理/8192附加绘制后18/18达标，
这两例实际只需要265/263张、误差约1.236/1.225px，未触及图源层级限制。
214是基准的显式配额，不代表SDK所有视口的有效容量；不据合成网格改变默认值。

下表为最大网格、不剔除面、扩展容量的5次均值，仅代表上述固定阶段：

| 曲面 | JS完整阶段ms | 同侧完整阶段ms | 最终误差px |
| --- | ---: | ---: | ---: |
| 起伏64800面 | 179.587 | 42.804 | 0.914 |
| 空洞57600面 | 87.443 | 26.365 | 0.914 |
| 折叠64800面 | 103.710 | 39.949 | 1.236 |

起伏用例的JS投影约27.35ms、压缩143.53ms、输入/规划/读取8.69ms；同侧
计数约8.00ms、投影加压缩30.47ms、输入/规划4.28ms、读取0.04ms。这说明
此固定输入的主成本不只是投影，不能只搬投影内核；也不能把这些分段均值
直接解释为真实交互停稳会同倍提速。原生同步原型没有生产分片开销。

## 原型的明确局限

- 这只是已选精确面的生产阶段。真实CBDAM块选择、浅视区间上界、候选XYZ
  采样、Worker传输、宿主UV拟合、GPU、网络和整幅视图调度不在计时范围。
- 当前实验同步完成，不具备生产所需的持久游标与取消点；长调用不能接入UI。
- 显式缓冲具有生产前空间报价，Native输入credit边界得到验证；实验尚未把
  这些缓冲接入ResourceLedger、跨线程授权和回执，不能宣称SDK预算闭环。
- 报告的暂存是指定数值载荷，不是总JS堆、分配器开销、Wasm容量或进程RSS。
- 合成索引网格不是实际CBDAM驻留/未提交模型；固定吞吐结果不是大倾角场景
  时延、30FPS或两帧输入响应的证明。不能据此调整原有期限和质量门槛。
- 夹具的投影深度为正、密度有限，未验证W趋零、无穷SSE或全部近裁剪退化
  分支。原型压缩算术不能绕过这些独立合同直接用于任意相机输入。

## 与桌面参考的关系

当前桌面源码`ratman/ratman/src/vic/cbdam/base/texture_refiner.cpp`依据纹理层
对应的CBDAM层、包围体可见性和已达地形层级决定误差；不存在SDK这一段逐面
JS对象生产、重建与二次打包。SDK保留独立屏幕像素误差后，需要额外的局部投影
证据，不能把桌面的层级差直接当作同等画质证明。应借鉴的是同侧模型读取、
已有输入的持久持有及有限推进，不是删除SDK的精度定义。

`grid_texture_quadtree.cpp`保留细化/粗化堆并按变化维护成员；其`extract_cut`
仍含整堆优先级重建，以及每10帧执行一次粗化的旧策略。桌面现有效果可作为
对照，但不能将这些实现细节当作Web的主线程时延保证。正式SDK测量任务继续
使用自身明确的游标、额度、最新视点和提交回执，与现有原生影像树接续。

## 正式架构与持有者

新增核心工作单元`surface_measurement_work`，适配层只传身份、视口与额度。
不保留当前逐面跨边界API，不引入另一种地形模型或外部图源内部节点。

| 数据 | 持有者与身份 | 退役条件 |
| --- | --- | --- |
| 驻留XYZ/UV | 原生不可变mesh资源的真实loan | 所有读取游标结束后释放loan；不另计一份几何 |
| 未提交采样 | planId、资源ID、冻结height inputs及Float32采样语义 | 计划失效/任务结束后释放采样工作；不得先物化整幅候选 |
| UV块/面布局 | 不可变UV身份与拓扑版本；高程导数另属mesh | 最后一个模型借用者释放；不能成为无预算全局WeakMap |
| 原始区域及压缩工作区 | 一个mesh/投影代次的测量工作句柄 | 紧凑结果已进入目标所有者或确认取消后释放 |
| 压缩描述符/wire页 | 同一生产工作句柄 | 归一化输入和必要宿主镜像均生产完毕后释放 |
| 规范区域/索引 | 原生不可变测量输入；规划器引用它 | 最后一个规划/历史/查询借用者释放 |
| 宿主紧凑镜像 | 独立ArrayBuffer所有者，按版本共享 | Worker发送/宿主接收回执后才转移/退休；GPU任务仍借用时保留 |

完整身份包含数据集、图源描述版本、mesh/UV ID、资源代次、候选planId或驻留
代次、投影矩阵、视口/DPR与算法版本。准入容量和误差策略不冒充投影身份。
相机变化只退休不兼容的投影工作；兼容网格、已下载图像和当前显示继续持有。

## 持久生产状态机

1. **打开输入。** 校验完整身份，取得驻留loan或冻结候选读取能力；不复制整幅
   XYZ/UV。候选读取沿用`terra_get_prepared_mesh_positions/uv`的真实采样定义，
   包含部分已生成数组、冻结高程和Float32舍入，不能用当前后台高程替代。
2. **保留便宜路径。** 原生侧生成/借用有预算的不可变块摘要；浅视完整块继续
   使用现有保守区间上界。只把无法证明的块细分到现有深度/面数边界并精确测量，
   不用逐面扫描替换所有视图的便宜上界。块域来源必须能支持后续按需收紧。
3. **计数。** 对选定的精确域有界投影/裁剪，统计实际原始区域数及摘要。计数
   不产生区域数组，也不申请按每面最坏14个扇形面的全视图容量。几何源和投影
   在count/fill之间保持同一不可变身份；变化时取消，不能接受数量恰好相同的旧结果。
4. **申请工作额度。** 确定原始区域、去重/排序/凸包暂存、描述符及wire页的总峰值，
   发出工作报价。Direct先授权，Worker先返回报价再按同workId/代次的grant续作。
   未授权不分配，也不在同一轮重复轮询。确认取消/终止前不退款。
5. **生成与压缩。** 按真实读取游标生产区域，保留现有裁剪、面向容差、谱密度、
   重复首成员、稳定组序、密度/面积归并规则和节点局部SSE。扫描、哈希碰撞、
   排序合并、凸包和输出均有固定工作单元游标；原型同步循环不能原样上线。
6. **申请规范输出。** 已知压缩结果数量后，为原生规范区域及必要宿主镜像独立
   预留实际空间；旧输入和旧显示仍计费。按wire页生产并校验后交接给不可变
   输入所有者。优先直接生产原生语义类型并转移所有权；不能依靠C/C++结构体
   内存布局碰巧相同做别名重解释。全部页消费完才能释放原始区域和压缩工作区。
7. **接续规划与发布。** 原生规划器引用规范输入，继续现有树、引用索引和输出
   授权。不再把同一份区域读回JS后重新打包。地形候选与已显示需求继续按原有
   完整替换组、UV拟合和实际提交回执交接，不能由实验吞吐结果跳过联合准入。

每个生产step同时约束工作单元和耗时窗口，给控制请求、相机与渲染真实主机
执行机会。固定step数不等于毫秒保证；分配、最终校验、引用重绑定也必须审查。
有限操作数检查点位于原生内部；一个step可在同一总预算内连续处理多个检查点，
只在窗口用尽或真实依赖/报价时返回紧凑状态。不能每64面跨ABI返回完整区域，
否则会重新引入已被否定的桥接成本。
未完成、容量等待、输入过期、源缺失、已完成使用不同状态，不把等待视为完成。

## 宿主消费与跨线程边界

宿主仍需为过渡图像、缓存回退、可见性和UV拟合计算局部需求。不能简单删除
`measurements.regions`，再用全mesh最大密度替代，或用已选节点误差按层级缩放
冒充任意子域误差。它们会重新引入图源过细、近远不一致和错误容量判断。

改为一个按版本共享的紧凑数值镜像，消费者内核直接读取区域行，不重建每行的
JS对象/三角形数组。浅视块域另带有限provenance码，保留按需收紧证明。直接
路径可在真实借用范围内读取原生输入；跨Worker镜像必须有独立的主机预留，
不能转移整个Wasm memory，也不能以RPC取消作为副本已释放的回执。宿主的
缓存、帧、分区任务和纹理过渡共同引用同一镜像所有者，迟到释放按代次校验。

首轮Worker仍应传必要的数值证据，不能为了减少字节变成每次纹理到达都等待
新的Worker误差RPC。新的异步往返可能把计算收益换成呈现抖动。只有证明某类
消费者不再需要区域后，才单独移除对应传输，不一次删除所有证据。

## 接入与退出条件

先将上述同侧生产做成核心可续作任务，接入驻留和未提交采样，冻结独立数学
对照；随后接入同一额度/回执、规范输入引用、紧凑宿主镜像与消费者，最后删除
产品路径中重复JS区域和二次打包。需要变更C ABI/Worker协议时一起升级，不做
开发期旧接口兼容；实验符号始终不进入SDK分发。

正式集成必须新增：真实CBDAM驻留/混合候选/分段采样、原始与压缩区域质量、
浅视及近裁面、极端数值和不可合并空洞、换图源/DPR/相机、内存增长、少一字节、
工作游标取消/迟到grant/线程退出、Worker与Direct一致性、低容量联合交接。
固定阶段的完整成本通过后，再用原目标/原期限执行真实飞行、快拉升推进、近地
斜视、弱网、长往返和完整发布门控。目标设备帧/输入延迟、实际步行和P0–P4
仍属总目标；本实验不结束这些任务。
