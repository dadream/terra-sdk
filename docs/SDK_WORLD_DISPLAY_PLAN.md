# 后台世界显示切面

当前完整计划的目标与历史缓存分开：相机版本一致且计划完成时，未来材质只依赖
该目标集、根覆盖或显式恢复所持有的图像。历史仍可决定保留的空间细胞与渐变
端点，不因曾驻留而成为新发布的必需图像。旧图离开视野并正常回收后，不应
阻断已经全部驻留的当前目标。计划尚未完整时继续继承已显示的细节，不能凭
临时根图撤销细覆盖。确定性旧实现反例、失败场景和最终门控范围见
[当前目标与历史缓存](SDK_MEASUREMENT_PIPELINE.md)。

本轮最终38文件冻结实现已通过19项baseline和完整SDK发布，366项/12条可见
轨迹通过；实际分发与归档分别核对。证据在
`viewer_verify_output/world_goal_material_20261020/`。最终大倾角停稳仍需
14.2–21.2秒，不能据此宣布工业级流畅度或完整P0–P4完成。

本增量落实P2中的已提交切面与后台后继分离。CBDAM地形、八根内部纹理树、
外部TMS/WMTS适配以及1.25px目标不变；本模块是WebGL派生显示计划，不是另一套
地形或影像选级模型。完整P0–P4及工业级交互验收仍需单独完成。

## 桌面参考与Web边界

桌面的`ratman/ratman/src/vic/cbdam/base/terrain_model.cpp`在更新线程推进地形和
纹理切面，再由`update_swap_cuts`交换供显示使用的结果；
`grid_texture_quadtree.cpp`保留细化/粗化队列和时间窗口。值得保留的是持久状态、
后台推进、完整结果发布的职责边界。SDK已有CBDAM/纹理调度，当前缺口在WebGL
显示端：交互帧仍重建派生世界拓扑、UV需求和后继交接。

Web不能照搬桌面50ms纹理更新窗口或共享可变线程对象。这里使用同一JS运行时的
两个独立时钟、可取消迭代任务、数值快照和实际GPU回执。后台仍与显示竞争主线程，
单个迭代器的4ms窗口不代表整个事件回调具有4ms硬上限。

显示回调的情况下前进。相机变化保留已提交世界切面，新的模型、图源或布局
改变则在资源时钟准备后继。

旧`ImageryFootprintCache`已移出产品依赖图。其原数值实现保留在
`tests/js/reference/imagery_footprint_cache.js`，仅作测试参照；测试不得要求
分发包重新携带已退出生产路径的模块。

## 覆盖、精度与发布

相机更新保留已经准备好的不可变地表。清空该准备凭据会使后台每次准备完，
都在下一次相机动画先于显示时被撤销，造成持续交互期间地形发布饥饿。当前
投影、可见掩码和SSE在显示时重算，地表只在模型或资源身份改变时失效。

地形输出报价与显示切面的依赖也必须分开。`MeshOutputPlan`可以正在为下一份
候选模型报价；在`setMeshFrame`实际接纳该输出前，它不得参与当前世界切面的
版本或取消判断。输出信封的`acceptSurface`标记该边界，且只有当前目标记录
能够采用这个已接纳计划，旧显示记录不继承新模型计划。否则相机运动会不断
替换未来报价，把已就绪模型的显示任务一并撤销。Direct诊断中曾在约3秒内
出现56次新构建、54次取消而仅一次完成，地形停在`display-cut-preparation`；
针对未接纳报价不得撤销当前付费切面的合同在旧实现失败。

相同不可变源布局的不同纹理目标共享记录，目标版本单独递增。在建任务持有
自己的输入数组和数值快照，不因连续相机更新改读新输入，也不因目标数组
变化被取消；完成一份结果后，再追赶最新目标。已安装完整足迹的UV续作和
几何交接可以继续，新的图片准入仍等待最新目标元数据。旧结果的粗化必须
经过当前SSE检查。该边界使连续输入不能永久饿死一个已付费结果，且不把
旧目标误标为当前精度达标。

相机、测量、目标、可用性、已呈现单元和交接目标等数值输入，在第一次
yield前冻结；随后逐片取得实际载荷借用。此前在几何或图像借用期间读取
后续目标，会混合两个时点的相机与目标。定向合同在旧实现分别复现快照
混入后续目标和同源任务被取消；修正后在单步任务期间持续改变相机与五种
纹理目标，仍能完成结果并在销毁回执后归零。

原生当前影像需求可以只覆盖投影ROI，不能直接当成持久世界足迹。后台保留
细节目标，并对尚未覆盖完整源网格的部分加入物理根覆盖，再由同一规范算法
切分成互不重叠的单元。相机转向时读取当前可见掩码，既不漏掉新露出的区域，
也不固定离屏精细图。

目标拓扑先于图片I/O准备。预期图片只表示数值目标，整组发布仍检查真实图像
和UV；粗化/容量决策另用冻结的实际驻留、实际GPU就绪集合。不能用尚未上传的
“未来粗图”授权退掉现有细图，也不能让图片等待尚未准备的目标元数据形成循环。

UV就绪与图像就绪分开：网格必须具备当前切面的完整UV，图像按各自世界分组
等待。某网格的一个细图未到，不应阻止另一个已就绪粗化组。切面行只持有共享
的就绪布尔对象，既能在提交后继续等待实际图像，也不会通过发布表保留其他
无主行或资产。

如果目标拓扑本身新增UV，而细图下载又等待粗化释放空间，则先发布一份粗化
切面：沿用上次实际提交的完整UV布局，只把可接受的旧单元目标改为已就绪
粗图；新细化保持原状。该切面与完整目标一起在后台准备、计费和取消，显示
只选择已就绪结果。旧UV不重建，旧数值行跨切片也有显式loan。粗化提交并完成
渐变后归还细图占用，细图与新UV随后正常交接。这对应桌面粗化优先的前进条件，
适用于需要几何裁剪的路径，不依赖提高预算、降低目标或拉长测试期限。

读取后继时检查源布局、UV和整组就绪，并按当前SSE拒绝过期的不可接受粗化。
真实容量交接仍允许原有降级路径。相机在粗化渐变中改变且当前精度不足时，
使用已保留的更细端点反向过渡，不增加采样器。Context恢复先恢复CPU中保留的
细节目标，再以实际GPU就绪发布，不能把恢复期暂时可用的根图当作最终细节。

缺少完整切面或某个UV时，已提交的可用细节继续显示；同一源网格以根图填补
缺口。这是影像覆盖，不改变地形标志或地面查询精度。Stencil先保留细节，再为
源网格填洞并增加已覆盖计数，最后绘制全局粗几何，避免全局根覆盖掉精细地形。
高精度直接裁剪的可选祖先索引退出时，原始驻留源网格仍是合法三角形超集。
已提交的普通UV单元也适用：在原浮点精度界限内，索引退休到后台后继发布
之间直接裁剪原始网格，保留同一精细影像，不能暂时退回根影像。超出精度
界限或不支持该shader的路径仍需真正的裁剪输出和覆盖。

准备完成不等于已经呈现。新的地表、切面loan与局部分组，只有在实际绘制或
已保留命令证明像素完全不变后才交接；相机/序号更新不能提前退休旧显示。

## 需求凭据与粗化布局合并

`WorldDisplayPlan`分别记录完整纹理需求的凭据与显示布局的版本。完成一个粗化
渐变后，后台仍会合并不再需要的细UV单元；但在相机、来源、目标、容量压力和
地形输出计划均未改变时，原完整布局依然可以为相同图片组提供完整UV报价。
图片不再仅因这项后台布局合并尚未完成而等待整份世界切面。

`demandSignature`保留原来的需求依赖，`signature`另包含粗化完成版本。安装结果
同时保存两份凭据；`targetState`与`imageGroupRows`要求需求凭据有效，世界任务
仍按完整布局版本准备后继。没有绕开几何输入、完整足迹选择、联合额度、实际
图片/UV就绪或GPU回执。地形输出计划退出仍会使需求失效，不能把只含继承图像
的交接布局当作已报价的新精细目标；真正的粗化压力变化也继续重新准备。

`tests/js/world_demand_receipt_contract.js`完成真实的粗化状态转换，并扣住后继
任务，检查旧完整UV行逐项不变、图片仍进入完整足迹选择、查询不执行同步
世界生成，同时验证新地形输出计划、实际容量交接、相机变化及销毁归零。
实际`474f963`模块在同一合同中返回waiting，新实现通过。证据在
`viewer_verify_output/world_demand_20261020/old-demand-negative.log`。

本改动没有消除世界切面的全量重建成本，也没有取消地形输出或UV生产的其他
准入等待。只有粗化完成引起的布局合并与不变需求分离；整体时延、最低联合
容量及工业级P0–P4仍需独立验证。

显示读取还必须独立于目标数组的登记时机。一个后台轮次完成了地形切面，下一次
纹理计划却可在显示检查之前换成新的draw数组；此前`request`只能按已登记数组
找到记录，便把同一地形暂时视作未准备。持续更新可反复落在这个窗口，即使已有
完整结果也不能交接新地形。

`request`现在可以按对应地形已有的规范来源memo定位已准备记录。显示侧只作
指针匹配，不归一化、扫描比较来源或运行世界生成器；新数组仍排到资源时钟，
由`collect`核对目标并登记。`demandPrepared`明确要求当前数组已登记，因此可
显示同一来源的旧完整足迹，不等于已批准新的图片需求。未准备的新地形不会
借用另一来源的结果。

等价目标登记后可以直接复用需求凭据，不产生新的切面安装事件。如果图片
已经在登记之前进入`preparationWaiting`，资源时钟在确认凭据后仍须显式唤醒
一次；没有新登记或没有等待者时不唤醒，避免让这一恢复路径变成轮询。

`world_display_alias_contract.js`在新地形切面完成后、目标登记之前执行实际
地形交接和绘制，使用实际图片生产适配器，验证发布、缺图0、无同步拓扑步骤，
登记前不得批准图片需求，以及登记后等待队列只唤醒一次。与失败门控哈希相同
的仅需求凭据版本在该合同失败，只修查找而没有补唤醒的版本也失败。反证为
`world_demand_20261020/old-alias-negative.log`与`missing-wake-negative.log`。

## CPU发布准备与GPU完成回执

`prepareResources`在轮询已有GPU回执之后检查地形发布，随后才因仍在途的批次
返回。CPU检查不再要求整个GPU队列先排空。连续相机绘制时，资源回调可能总在
刚提交的一次绘制后运行；若先返回，就算网格、UV和世界足迹都已就绪，候选也
可能一直停在接纳时的`prepared`状态。该状态不是可绘制证明；`ready()`成功后
才进入`gpu-submit`。

发布检查仍读取各几何、索引和UV自身的实际就绪状态。准备结果不改变旧显示
所有权，不发送地形提交回执；显示入口仍等待GPU批次完成，真实绘制后才交接。
资源回调不绘制，显示入口不运行这项CPU准备，原两批在途上限保持。高程模式
只等待几何，不再等待该模式未启用的纹理世界切面。

`terrain_publication_clock_contract.js`在高程与纹理两种模式中保持旧绘制fence
未完成，验证后台能准备已就绪的新地形，却不能伪造显示回执、退休旧显示或
提前绘制；完成fence后才发布新地形，销毁后同步对象和账本归零。与第二次
失败门控哈希一致的旧Renderer在该合同失败，证据为`old-cpu-publication-negative.log`。

## 资源归属与唤醒

准备工作和驻留显示元数据进入现有`ResourceLedger`，不扩大总额。工作阶段借用
几何、测量及缓存项，结束、取消、暂停、换源、context丢失和销毁均释放；
驻留切面只保留数值行，不持有图像和地形载荷。旧切面被生产者退休后，最后一次
显示借用仍计费；最后借用释放前，公共发布表必须解除对旧行的引用，旧UV需求
也必须清除。

缓存`contentRevision`仅随插入/删除变化；loan归还等所有权变化不得触发自己
重建。普通细图上传推进现有发布就绪；实际粗化和容量变化才影响相应拓扑输入。

压力输入在资源时钟采样。图片调度会在一次重试前暂时清空自己的失败标志，
这个瞬时状态不能让已付费的世界元数据重新变成“未准备”；否则请求在自身
准入检查中撤销了依赖。切面安装后显式唤醒等待该元数据的图片队列，不能只
请求一次显示或后台回调。定向诊断曾记录三张图的`canFit=true`、几何与切面
均就绪，却仍被旧等待标志停住；相关确定性回归在补修前失败。

普通细图到达只推进发布就绪，不让全部世界足迹失效。压力版本描述实际根
覆盖及正在交接单元的可用回退路径，不使用整个缓存的内容/可用性计数。
无关图片插入不会撤销已付费切面；交接图或根覆盖恢复仍会唤醒更新。活动
交接也不会因一次请求暂时清空失败标志而消失。旧实现的定向回归在无关图片
插入后构建数从2增为3，新实现保持2；另检查必要交接与覆盖恢复的依赖变化。

图片准备以参与该组的不可变几何为依赖，不等待整张新地表替换完成。旧地表与
新地表可以并存；若反过来要求整张新地表先呈现，便可能与新地表需要的图片和
UV形成循环。Direct弱网诊断曾记录相机/计划均为86、所有46个待请求组的图片
必要容量检查均通过，GPU队列空闲，却因地表仍在交接而让120张图片停在准备
等待中。当前仍检查真实几何输入、UV生产通道、已付费目标元数据和完整报价，
仅移除整张地表一致这个不必要的前置条件。

纹理模式的图片组直接借用已计费的目标切面。按该组实际涉及的源网格读取
完整规范UV足迹，跨切片持有数值切面loan；完成报价元数据后归还。不为每个
下载组重复全视图的hull遍历、纹理树切分和图像缓存快照。其余未来图片只在
这里贡献UV目的地，不伪造实际驻留；它们的图片就绪仍由各自世界发布组检查。
实际几何借用、已就绪图片借用、完整UV定价与统一账本保持原约束。高度模式
没有纹理世界切面，仍按自己的实际输入准备。定向回归证明旧路径在已经准备
的单网格上重复读取hull七次，新路径零次且完整UV目的地集合相同。

已生产组的准备借用，在图片实际就绪且对应不可变几何已有提交凭据后归还。
凭据由`WorldDisplayPlan.commit`取得，必须仍指向几何的实际提交切面；不能把
未来完整目标行数组与当前过渡数组的对象身份相等当作唯一凭据。数值切面、
GPU资产以及实际渐变端点各自保留原所有权，归还准备票据不会提前退掉这些
资产；后继UV需求也继续存在。模式切换取消旧准备组。两项定向回归分别在
旧准入条件及旧数组判断下失败，并检查提交前不得交接、图像未到不得交接、
交接不退还驻留资产和销毁归零。

资源更新按最多一个显示间隔合并；有准备结果时提供有界显示机会，显示回调
缺席则到期继续上传。显式显示和相机请求保留优先权。GPU异常唤醒允许稍后
重试，但永久分配失败的退避上限仍是后续工作，不能将定时重试称为完整恢复。

必要上传与可选可见性观测分别仲裁。Direct诊断曾在图片和UV全部完成后，
连续1秒以上保留相同显示误差，同时不断提交零分配字节、仅持有观测目标的
资源批次。显示机会窗口已过期，后台观测仍在每轮先于显示加一道fence。现在
