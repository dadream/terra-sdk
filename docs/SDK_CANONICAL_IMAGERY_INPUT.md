# 规范影像输入

`Terra::frame`的`imagery_input_work`将区域生产与规划器的最终输入所有者接通。
现有C API的整批和分段入口都使用这个事务。CBDAM、八根纹理金字塔、外部
TMS/WMTS适配、纹理容量及像素误差定义保持原合同。

## 语义和版本

测量、压缩、输入归一化和规划共同使用`measurement_region`，包含区域数值、
显式存在标记及来源域码。不存在的投影按标量处理；存在但W为零的投影仍执行
三角形支持域和无穷误差判断，不能用全零矩阵猜测字段缺省。矩形深度包络可以
只有投影及非负分子上界，不要求虚构三角形。未提供的域码为`UINT32_MAX`。

C ABI46沿用44引入的`terra_imagery_region_v4`：前168字节为21个双精度数，后8字节为
`flags`和`domain`两个无符号32位数，总长176字节。Worker45采用同样的区域
字段顺序，通过`Uint8Array`传输混合布局；不存在的字段由标记解释，不能将
整数来源位当成Float64/NaN元数据。Wasm、浏览器与Worker必须一起构建。
不保留ABI43、旧区域结构或旧Worker协议的兼容入口。

原生规划器区域载荷由每行168字节增至176字节。真实归属和准入报价同步计入
这8字节，整页桥接暂存最多256行；总资源预算、纹理数量和质量目标没有上调。
Worker此前每行也是176字节，本次改变的是混合数值编码，而非压缩或量化。

## 构建、交接与归还

1. `imagery_input_work::work_bytes()`报价事务状态、成员表、新规范所有者/控制块、
   区域和凸包容量，以及提交时成员身份索引的包络。已借用的旧输入不重复报价。
   `stage_input()`在实际分配前检查全部额度，差1字节即拒绝；空事务不分配。
2. `append_surface()`立即建立最终规范所有者，区域和凸包直接写入它预留的数组。
   新成员、旧成员及其他事务有各自的真实归属。形状未满足不能提交，非法数值
   会使事务不可提交；取消显式释放该事务。
3. 已完成的`surface_projection_work`和`surface_layout`可按最多256行/点直接
   写入同一构建器，不经过C结构体别名、JS对象恢复或ABI重新打包。无效来源
   范围在写入前拒绝。该接口复制最终语义行，不声称与压缩暂存零复制。
4. `commit_input()`将同一成员数组和规范句柄交给既有规划器，并转移其收费归属。
   不创建第二份区域数组。归一化仍由既有有界更新游标完成，成员重排只改变
   绘制编号。`read_input()`及凸包读取只允许完全归一化的快照，每次最多256项。
5. 输入句柄继续持有原控制器账户；清空、替换或取消不会退还其他借用者仍持有
   的数值。最后一个真实借用销毁后先释放实际存储，再归还对应字节。其他控制器
   不接受它；原控制器清空后，同账户的完整事务仍可正常提交。

原生`begin(vector<imagery_surface>)`仍是直接原生调用的输入形式，和事务接续
同一个规划实现。其`input_work_bytes()`是成员/规范所有者报价，不含事务状态；
使用构建事务的调用方必须采用`imagery_input_work::work_bytes()`。C API统一
使用后者，没有保留第二套C转换/暂存实现。

## 验证与当前边界

原生合同检查真实分配、少1字节拒绝、实际分配失败、提交无区域规模分配、
未完成/非法输入、借用重排、同账户清空、跨账户拒绝、归一化读取和先释放后退款。
真实CBDAM模型的直接生产与逐行输入使用相同的节点和局部误差。Wasm32在33组
既有实际模型测量上核对同侧交接、来源码、归一化及最后借用释放；产品C API
另外检查分段取消、内存增长、全零投影和缺省投影的差异。

这一步并不宣称减少了旧实现已有的移动交接成本：旧的分段输入本来也不要求在
提交时复制整幅区域。本次是将最终所有者前移、保留显式语义并接通同侧生产。
Web、Worker及Direct默认使用[原生生产器](SDK_NATIVE_MEASUREMENT_API.md)，接通
选择性收紧合并、独立封存、阶段报价、直接规划和镜像读取。
[紧凑宿主镜像](SDK_HOST_MEASUREMENTS.md)直接使用独立计费的数值行。模型跟随
实际网格生命周期；历史和待发队列只持有数值loan。不能据生产路径切换本身
声称大倾角时延已改善，也不能替代P0–P4场景和设备验收。
