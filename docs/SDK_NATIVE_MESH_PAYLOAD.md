# 原生网格载荷的所有权计数

`sdk/src/c_api/mesh_payload.hpp`只维护真实XYZ与共享UV数组的容量。它不改变
CBDAM、八根纹理树、SSE、地形生成额度或共享ResourceLedger上限。C ABI46与
Worker45的字段和语义不变，Wasm及其消费者一起重建。

此前每次`terra_mesh_payload_bytes`都扫描mesh和UV弱注册表。Direct/Worker在
原生调用结束后核对全部资源账户，影像测量的小步推进也会触发这个扫描。
冻结地形的三条Direct轨迹插桩记录了261037次查询，累计约2.7秒。该剖析有采样
开销，只用于定位热点；`fullUpdate`包含异步等待，不能据其墙钟时间宣称存在
同样长度的单次主线程长任务。

XYZ计数随`terra_mesh_resource`所有者存活。UV拥有独立的`mesh_texture`，各
mesh和core读者共享它的实际分配。填充成功后记录vector的capacity，最后一个
所有者销毁数组后才扣除字节。空描述、弱注册表和额外读者不重复计费。
载荷查询直接读取账户总数，不再遍历注册表；逐次核验和真实回执仍保留。

内部复用`core::payload_budget`的共享所有权计数，数值上界仅防size_t溢出，
不构成另一套准入策略。实际生成仍先通过原有mesh credit和容量检查。UV填充
后先记录它的所有权，再执行可能失败的注册表插入；XYZ记录后以编译期确认的
无异常移动交给资源。溢出显式返回状态，兼容既有Wasm无异常构建。
失败或取消保留下来的数组继续计费，临时局部数组由原生成额度覆盖。

两种借用边界保持明确：C API的`acquire_mesh_resource`仍阻止manifest重置，
每次acquire都须release；core读者可独立保留UV数值，注册表退休不能替它退款。
新增真实C API/core交叉合同在旧实现中因提前退款失败，在新实现中通过；它还
验证重复借用、重置拒绝、UV数值不变、最后释放归零和其他context隔离。

固定数据诊断、编译、完整基线、发布和本机部署证据保存到
`viewer_verify_output/native_slice_profile_20261020/`。性能收益以最终对照和轨迹
结果为准，不将计数热点关闭等同于整体交互或P0–P4完成。

最终固定视点使用相同389块几何，每2万次查询的五轮中位数67.7ms变为1.13ms，
返回13316160字节相同，373个draw的完整切面和质量字段相同。整体影像规划1354ms
与1378ms，未显示端到端改善。19项完整基线、实际分发包和发布门控通过；
ASan/UBSan/泄漏检查通过。Intel Vulkan浏览器348项、12条轨迹满足原1.25px
目标，采样白屏/缺图为0，资源不越176160768字节总额，测试退出后请求/资源归零。
大倾角停稳仍6.8–14.2秒，部分Direct提交与帧间隔超过工业级目标。

首轮Wasm门控发现辅助类的throw不兼容既有无异常构建，已改为显式状态；
最终完整基线重新从头执行，没有复用早先通过的前缀。首次独立Sanitizer脚本在
sudo环境缺少rg而漏列源码，链接失败；修正源文件枚举和数量检查后，完整
原生C API合同在实际ASan/UBSan及泄漏检查下通过。失败日志和最终证据均保留。
