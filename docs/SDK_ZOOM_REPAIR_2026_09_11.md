# 缩放影像与资源调度修复（2026-09-11）

基于 `75a4ca45d83b7ed4f6ac63beaf986c55d8dbdd4f`，替代上一轮“导出所有驻留地形”和“各地形片独立选择影像等级”的实现。本轮保持 SDK 的独立影像 LOD、Wasm ABI、数据格式和默认预算，不移植 nav3d 客户端。

## 改动及约束

- 对所有可见地形共同建立影像四叉树切分，再将各地形片映射到叶影像。一个地理区域不会同时成为父级和子级目标，资源压力按整片影像区域处理。滞回键使用影像瓦片标识，不依赖地形遍历顺序或片段标识。显式 terrainBoundImagery 兼容模式仍保留旧策略；产品 SDK 默认使用独立空间切分。
- 投影导数残差先投影到屏幕再求安全上界，取分量区间界与原世界空间范数界的较小者。仅可见空间分块参与选级，实际显示质量也按对应影像格的分块计算。没有用采样值代替安全上界，没有放宽 1.25 px 目标。
- 请求从根覆盖或最近的已驻留祖先直接推进到所选目标，不必逐层下载全部中间影像。终端目标各自占用一个过渡名额、各自提交；同根的大量目标不会组成超过过渡容量的不可调度大组。保留已有细节，直到替代纹理可用；呈现遍历排除不与当前几何相交的兄弟影像。
- C API 只导出可见地形及独立根覆盖，预分配计数与实际导出保持一致。驻留 LOD 数据不等于当帧绘制数据。可见切分及已提交记录未改变时复用上次网格输出；缓存容量不足时不逐个挤掉本帧即将需要的网格。
- WebGL 请求 stencil 缓冲。在相机预览或新旧地形交接期间，先标记详细地形已覆盖的像素，再让根覆盖填补空白，避免根面覆盖细面或发生深度冲突。稳定帧只画可见目标。
- `quiescent` 现在要求相机计划和呈现版本一致且交互已结束，避免把只更新了相机的过渡帧误认为收敛。

## 验证

- CMake 编译及 16 项基础测试通过，原生 SDK 24 项测试通过，编译日志无 warning。C API 回归要求不可见叶片不进入绘制载荷、根覆盖仍保留；原生/Wasm 一致性及可复现构建通过。
- 新增空间切分回归：无祖先/后代重叠、地形顺序及等价细分不影响目标、预算限制、可见性过滤、影像键滞回。新增终端目标数大于过渡名额的调度回归，预览 stencil 和相机收敛回归。
- `verify_baseline.sh` 非 GUI 门控通过；已经单独通过的 build/native SDK/golden 步骤通过 RUN_* 避免重复。未声称本机不存在的 X11 显示服务提供了 viewer/nav3d GUI 验证。
- `verify_sdk_release.sh` 在 Web 步骤因为 WSL 无可发现的 Chromium 停止；用本机 Windows Chrome 执行同一仓库 runner/checker，原图像阈值保持不变。发布包、原生消费者、SPDX、站点打包另行完成。设备人工验收仍按仓库约定由所有者完成。

## 已知局限

固定 256 张物理纹理预算下，这组视角仍是“精度受限”，保守误差未达到 1.25 px；不能以请求完成或精确绑定比例 100% 宣称质量达标。原始影像自身或相邻等级之间的色差不由 SDK 重采样消除。

当前可见细地形仍需要完整网格。缩放返回可能保留更多可见细节，因此帧载荷及必须驻留的几何工作集仍会超过 8 MiB 的闲置缓存预算；本轮没有把该预算伪装成整个渲染器的硬内存上限。未变更帧可以复用原生输出，但 Wasm 到 JavaScript 的帧读取仍有复制成本，影像测量和规划仍在主线程。以上是剩余成本，不是已经解决的功能。

工程证据位于忽略目录 `viewer_verify_output/zoom_repair_*`。使用普通 WSL Git 提交和推送，不执行 preflight。部署采用独立静态站点目录，校验资源哈希后仅切换 edge 服务；terrain/imagery 后端不受本次客户端改动影响。
