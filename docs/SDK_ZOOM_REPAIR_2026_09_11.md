# 缩放影像与资源调度修复（2026-09-11）

## 2026-10-07 地形与影像管理增量化

本节记录基于 `8d1db07` 的后续实施。参考 nav3d/viewer 的高程包围体、持久切分和后台局部更新机制，按 SDK 的独立影像精度、Worker 所有权与字节容量实施，保留下节已修复的细纹理保护和呈现屏障。

- 解码高度缓存保存实际米制最小/最大高程，通过独立高度版本反馈给地形控制器。已知区域更新包围体和相关优先级，未知子块继承父块的保守范围；子块的新高程向祖先扩展范围。相机未改变时，高程到达也能触发更新。格式与 C ABI 结构布局保持不变。
- 地形容量预测改为可续接的优先队列；候选节点、模拟切分和优先级缓存跨批次保留。倍增/二分试算复用相同视图的测量，不再每次细化全量扫描候选。预测受每轮优先工作数和时间预算约束，完成前保留已有覆盖；视角、高度范围或容量改变后重新预测。收敛且资源未变时直接复用完整切分。
- 影像节点保存实际 `split` 拓扑。新测量版本沿已有分支分批评估，构造当前可见切分引用，再先粗化、后细化；相同视图不重做拓扑变化。完整覆盖的中间结果可逐批发布，质量中的 `planningComplete` 区分继续规划与资源受限，不能将中途的粗覆盖报告为收敛。
- Worker 将数据提交、失败/重试和呈现回执放入优先控制队列，在测量、分片及网格准备的检查点处理。视角版本更新使过期工作在检查点终止；每个独立影像消息只推进一轮原生规划，运行时按已有地形帧继续。取消候选、换数据集及销毁时清除关联的测量和计划引用。
- 已显示网格、相机及请求需求均不变时，Worker 一次消息最多续接八个有界地形批次，每批处理控制队列，不要求主线程重复确认相同内容，也不调用假的呈现回执。网格、视图变化或新请求出现立即发布。屏幕测量版本与容量准入版本分别管理，资源回收不会使同一视图的实际表面测量失效。
- C API 保留最近 1,024 个不同已发地形请求的有界元数据，允许规划期间请求前沿变化后的晚到结果及失败回执。仍拒绝从未请求的数据，换数据集清除保留记录，解码数据仍受原有字节容量约束。浏览器回归确认旧的“只认当前帧请求”会把正常晚到结果误判为不存在并触发重试，因此本轮同时修复这一异步生命周期问题。
- 按 UV 和索引内容共享裁切模板，哈希命中后逐项核对数组，跨高程变化复用拓扑与精确分片字节成本；新位置按重心权重计算。模板、索引/UV 所有者及裁切结果共同计入 2 MiB LRU 上限。使用现有 UV 空间块排除不相交的面，保留原始三角面顺序；大三角批次和预算合并生成器定期让出 Worker。
- 新增 `terra_accept_imagery` 将 JS 字节预算接受的局部粗化反馈给原生控制器。被拒分支保留原始屏幕误差需求；相同资源版本下不重复尝试已被拒绝的切分。容量、可见覆盖、网格或分片资源释放使准入版本变化后重新入队，局部误差显著增加也可恢复尝试。默认 1.25 px 目标与已有纹理/GPU 容量不变。
- Wasm 编译与链接改用 `-Os`，保留浮点语义、Native/Wasm 对照和可复现构建验证；不放宽原有 512 KiB 包门限。

回归新增实际高程改变可见性、同视图零拓扑重建、准入拒绝后需求保留及容量恢复、异步与同步分片字节一致性、拓扑缓存上限、数据/回执优先处理、过期视角取消和候选引用释放。真实 Worker 用分批继续完成独立影像规划，保留旧接口的同步兼容路径。

局限：时间预算约束主要工作循环，单次局部事务、输入复制、输出序列化及提交解码仍有开销，不是整条消息严格 4 ms 的承诺。视角变化仍需重新测量当前可见需求，只持久化实际拓扑；不同 UV 或索引的网格不能复用裁切模板，缓存压力会淘汰模板。高程不足时使用保守父范围，不假设未下载细节已知。资源仍由既有分池预算管理，本轮没有改成统一 CPU/GPU 分配器，也没有增加平面自适应 LOD、多层影像或桌面客户端依赖。真实图源层级、缺图和层间色差仍由上游决定。

本轮只更新本工作站 `terra-sdk-web-local.service` 的 18766 服务，49 服务器继续提供数据。

## 2026-10-07 持续缩放后纹理退化修复

本节记录本轮后续修复。下方“管理机制优化记录”中的整幅误差重规划、无界误差退回全部根纹理，以及“粗目标就绪后替换细纹理”的策略已被替换。

原因由同一真实视角、同一地形和同一 134 张目标纹理预算的对比确认：包围盒最小投影深度为 348.5 m，而可见三角面的最小深度为 12,479.6 m。旧测量把盒内空白当成表面，放大精度需求；随后规划器用最坏误差重新规划整幅影像。最后一次放大时，64 张仍在 GPU 的 level 12 影像被粗父级覆盖，规划停在 153.23 px，并错误解释为容量限制。矩阵布局已单独核对，不是本次原因。

本轮实现：

- AABB 只承担空间筛选。部分可见、近面相交或深度差明显的块继续访问缓存的三角面树，对真实表面进行齐次裁剪，只统计可见 UV 和投影导数上界。三角面导数按不可变资源缓存。测量通过生成器分批推进，Worker 每批最多八次推进或约 4 ms 后让出执行时间；单次三角批次最多 64 个面。
- 影像控制器保留空间节点、切分历史和每个测量版本的细化/粗化优先集合。Worker 通过 `terra_begin_imagery` / `terra_step_imagery` 每轮最多 16 次拓扑变化、64 次优先工作、4 ms 推进，完成后发布候选影像切分。旧同步接口及全部 v1/v2 结构布局保持兼容。时间预算约束工作循环，输入复制、输出序列化和单次局部事务还有固定开销。
- 请求精度始终保持 1.25 px；可实现误差只描述已接受切分，不替换请求目标。删除最坏误差触发整幅重新规划的第二遍计算。预算不足时，先保留历史，再通过低误差兄弟组局部粗化为更紧迫区域释放名额。原始测量需求保留，容量改变后重新继续；无界区域只影响自身，保留已有切分，不阻塞其他有限误差区域。
- 分片容量预估仍计算实际裁切字节，但只合并需要释放资源的兄弟区域，明确标记该区域的容量粗化决策。不放宽全视图目标，不清空原生切分历史。
- 实际提交的细纹理被保护到下一次真正替换提交。父级已缓存也不能因缓存命中覆盖仍超过粗化滞回误差的细区域；误差满足 0.8 倍目标、区域退出视图或明确的局部容量决策允许粗化。新地形候选只有在当前细纹理所需的兼容分片也到达 GPU 后才能替代旧切分。
- 分片阻塞记录随资源释放、视角改变或容量增加失效，可以重新入队。闲置地形的历史分片不再永久占用显示保护。恢复后清除阻塞状态；质量输出列出投影、纹理预算、分片预算和图源层级等实际限制原因。
- Worker 增加独立影像消息，按已有地形序列继续规划，不要求生成新的地形帧，也不再次传输网格。主线程按相机、图源、序列及预算版本接受结果。资源事件触发更新，等待期间不轮询上游。Worker 保留相机矩阵副本，避免可转移消息将自己的规划数据解除所有权。

新增回归覆盖空包围盒误差反例、异步测量一致性、局部分片预算、缓存粗父级保细、新地形兼容分片屏障、有界规划继续、局部无界投影、容量再分配与恢复，以及不产生地形帧的 Worker 影像更新。未增加默认缓存容量，未修改 terrain/TMS 格式，未放宽图像验收阈值或 512 KiB 核心包门限。

本轮仅更新本工作站的 `terra-sdk-web-local.service`，端口 18766。49 服务器继续提供数据，不部署应用到 49。真实图源层级上限、缺图和不同层级原图色差仍属于上游约束；无 Worker 的兼容宿主仍同步计算。有限预算下的局部质量差异可以存在，应由实际误差及限制原因解释，不能承诺所有视角都达到目标。

## 2026-10-07 管理机制优化记录

下面的 9 月记录是历史状态。本次在 `feature/miniprogram-sdk` 工作树实施管理机制优化，保留桌面端源码作为冻结的比较基线：

- 地形使用持久细化/粗化优先集合，先粗化，再按每轮拓扑变化数、优先级计算数和时间预算推进。相机变化时分轮重新评估，完成前保留最后完整切分。数据到达只更新就绪状态；未变视角不全量计算优先级。容量预测预留粗化滞回，选择全视图统一的可实现误差。
- 根和细节解码记录、高度层次、不可变网格各自缓存。增量 C API 导出内容编号，Native/Wasm/Worker/主线程按新编号复制；旧呈现资源和唯一候选资源分别引用，GPU 呈现确认后释放旧引用。v1 完整缓冲区按需生成，产品 Web 不读取该缓冲区。
- Web Worker 拥有 Wasm、地形更新、表面误差计算、影像切分和纹理分片准备。主线程即时更新相机并显示已有覆盖，只上传新增资源。右键拉平/旋转不会使已有网格、共享索引或相同网格/瓦片的分片失效；视角实际需要的新瓦片仍按误差请求。
- 影像空间切分核心移入 C++，各地形片共同贡献需求。持久影像节点按相邻等级从粗到细推进，可见兄弟组的图像和分片都达到 GPU 后一起替代父级。尚未就绪或失败时保留父级覆盖。请求目标、预算可实现精度、实际呈现误差分别报告，预算受限不冒充达到请求精度。
- 在请求之前计算分片实际字节量；不足时调整整幅影像切分。地形容量同时约束工作网格与根覆盖，GPU 几何容量包含显示切分和一个候选切分。分片预留显示、父级、子级过渡空间，按需回收闲置分片。影像容量计算包含解码图像和 GPU mipmap；请求槽一直持有到 Worker 解码/提交完成，限制传输队列。
- 增量 Native 解码池限制 16 MiB，高度池限制 32 MiB；网格闲置池限制 16 MiB，当前/呈现网格由拓扑容量另外限制。Web 大视口几何/分片池各为 32 MiB，小视口各为 16 MiB，分别包含其 CPU 所有者对应的 GPU 工作资源；这些池不等于浏览器进程内存。Wasm 线性内存上限仍为 256 MiB，JS 对象和浏览器驱动开销另外存在。缩小预算时保留先前已接受的过渡容量，较粗切分呈现后再收紧。
- 404/410 按图源/数据集保存负缓存；临时失败有有限重试和冷却，在后续视角或人工重试时重新尝试。暂停、销毁、换源和 context loss 停止/失效相应任务。拾取和表面采样使用实际呈现的地形资源。
- Worker 规划失败时撤回本次候选帧，保留已呈现资源，后续有效更新可以继续。屏幕投影出现无界误差时，整幅视图保留根影像覆盖并明确报告投影受限，避免无效误差驱动大量细纹理请求；投影恢复后重新细化。
- 根地形分批到达时，覆盖不完整的候选帧不能获得呈现回执。新数据或视角触发更新时撤回该候选帧，继续推进，并保持已呈现切分的引用；否则单候选约束会把新到数据挡在更新窗口之外。真实 Worker 回归延迟返回最后两块根地形，并要求渲染器只确认完整覆盖，验证恢复收敛。
- 相机预览矩阵已是新视角时，正式帧即使复用同一网格，也必须提交新视角的影像规划；仅在规划版本也一致时采用元数据更新捷径。否则纹理计划会停在旧视角，已下载瓦片也不能表示新视角精度达标。

### 原因与实现

1. 原实现的完整覆盖候选需要渲染回执才能再次推进 Native；回执又要求优先队列完全更新。超过一轮有限扫描的候选会形成等待环。现在回执确认已经可安全保留的显示切面及其 CPU/GPU 资源所有权，不再等待最终选择或纹理精度。`currentSelectionReady`、目标几何完成和精度判定仍独立存在；尚未选完或影像尚未规划时保留根覆盖。候选上传及新旧切面交接仍有屏障，不能任意丢弃正在显示的资源。
2. Worker `step` 先发布地形帧、不可变新增资源和数据请求，不再先等待全部影像测量。影像通过独立 `imagery` 消息继续。尚未有规划的切面只建立根纹理 UV 映射，主线程不代替 Worker 进行完整表面测量或全局切分。已提交细纹理继续由呈现记录保护。
3. 测量和分区容量计算保留生成器游标，每次消息约 4 ms 后返回 `pending`，下轮接续；中途换相机、切面或预算则撤销对应过期计算。Native 扫描的额外批次也受总时间片约束。数据提交和呈现/丢弃回执优先处理；分区不再作为可递归阻塞地形的控制消息。排队地形优先于影像和分区；过期分区在检查点取消。
4. 每张网格最多导出 64 个 UV 测量区间，对同格可见区域取范围并集和误差最大值，不输出与可见三角面数量成正比的区域数组。近面仍裁剪真实三角表面；没有使用空 AABB 代替真实表面，也没有降低误差上界。渲染器按当前测量版本缓存纹理格的解析误差，减少静止帧重复遍历测量区间。
5. Worker 错误、RPC 超时和消息发送失败会一次性拒绝旧 RPC、终止旧实例并触发恢复。Runtime 保留当前显示切面与地形字节缓存，重建实例并加载当前 manifest、视口和相机；只重放新实例实际请求的记录。恢复后的更新必须真正进入调度，不能只设置待更新标记。新实例网格键包含 Worker generation；旧实例的网络提交和迟到回执不能污染新实例。

恢复在 30 s 内最多自动尝试三次，并采用递增延迟；持续失败保留画面和错误，可通过既有 `retryFailed` 主动重试。主动销毁不会触发恢复。Native 帧序号属于该 Worker 上下文，重建后从新实例起算，资源状态中的 `workerGeneration` 标识实例。

本轮保持四倍尺度跳变立即退休，并增加缩放尾段条件：Worker 连续观察到尺度稳定至少 160 ms，且相对当前任务变化超过 10%，就采用最新相机。该条件只检查投影尺度，不按相机任务年龄重启；纯平移与小幅旋转继续接续。160 ms 是工作接管的静稳条件，并非最终加载时限。尺度变粗超过 10% 的新周期带有粗化意图，避免最后不足两倍的一段丢失粗化调度。

粗化周期固定其相机和不可变模型切面，按现有四毫秒预算接续包围体、精确测量、Native 规划和分区拟合。每轮退休后才能采用新切面，显著尺度变化仍可中断旧周期。近地细化与平移继续跟随最新地形并复用相同内容 ID 的测量；全交互固定整轮切面会令新地形只能收到根需求，因而不适用于这些路径。固定切面的所有权只覆盖一个影像任务，不清空缓存或重置 Native 历史。

分段拉升又确认了重复计算问题：区域高度停稳 45 秒后，无缺失几何且旧细纹理已经退出，Worker 仍在对固定切面的大量过采样模型逐个精测。粗化周期现在用有限的包围体误差上界直接驱动 Native SSE 金字塔，跳过模型的三角形重扫；误差为无穷的模型仍须精确裁剪。源纹理本身不必已经达标，Native 会按上界选择所需纹理层级，显示端只在相应 GPU 纹理就绪且误差达标时退出细节保护。上界可能偏大，只会多要纹理，不会低估误差。若完整拟合未达精度（包括预算或层级限制），则对仍使用保守上界的可见模型执行精测，保留已有精确结果及可靠的不可见判定后再规划。纹理共享全局预算，未报错单元的上界高估也可能占用容量，因此不能只重测报错单元。同一相机周期每个模型最多精测一次，后续切面继续复用精确结果；真正的容量或层级限制仍如实报告，不会清空整批测量。同一相机版本的后续地形批次保留粗化意图，避免一次中间切面完成就退回精测路径；相机版本改变后重新判断，平移的新版本不继承。没有延长验收等待或降低精度门限来代替这项优化。

后台接续还需摆脱主线程的逐片调度。旧路径每计算约 4 ms 就返回 RPC，主线程若正进行数百次软件绘制，下一片会等数百毫秒；待计算工作并未锁死，但 Worker 大部分时间闲置。现在首个可用需求仍立即发布，其后 Worker 可在一次 RPC 中自行接续最多八片、约 32 ms 的软时间预算。每片之间让出事件循环并处理接收、数据控制消息；发现较新的相机通知时立即交回调度。普通细化遇到排队的地形或分区任务也立即让出；当前粗化可先完成这个有界批次，再交给同一视角的排队工作，避免连续地形轮询再次令粗化饥饿。原生每轮拓扑变化与四毫秒计算预算保持不变，未扩大单轮事务。新增回归核对多轮 Native 工作能在一轮 RPC 中推进，以及首需求、排队工作和相机的中断优先级。这对应桌面端独立后台模型更新的职责，不要求主线程每画完一帧才允许后台继续。

固定切面还要求匹配 Native 的资源所有权协议。Worker 的 CPU 副本仍有效时，Native 注册表中的同一模型可能已退休；完整规划曾因此返回 `TERRA_STATUS_NOT_FOUND`（7）并重启周期。Worker 现在用 Native 已支持的可选模型引用为零的独立测量输入，传入其拥有的 UV 范围、投影测量和 hull。返回的绘制仍按原来源索引关联 Worker 的资源 ID，显示端继续过滤过期模型。普通 Native 调用对缺失非零模型引用的检查保持有效。真实 Wasm 回归同时验证这两种输入和返回标识，未改动 C++ ABI 或地形所有权。

当前相机的保守测量现在可以用于粗化过渡，即使精确计划的地形切面尚未与当前切面完全一致。显示端仍按模型 ID 过滤结果，未测量的新模型按未知误差保留细节；完整精度就绪仍要求当前切面的每个目标资源均已规划或测量。已经进入 GPU 的粗纹理，其当前保守屏幕误差不超过 1.25 px 时，可结束旧细分支的视觉保护，不必等待整轮精确拟合结束。

后台推进后还确认了完成状态的过度绑定：相机已经停稳、Native 多次完成粗化计划，但 Runtime 要求调用前的地形帧对象仍为当前对象，又因优先级或记录状态发布而将结果一律标记未完成。当前相机的粗化完整结果现在交给渲染器按不可变资源逐项验证；仅当当前目标均已规划或测量，才允许完整状态。未测量的新模型仍阻止完成，退休模型仍过滤，旧相机不能走此路径。真正画面就绪仍须当前几何、GPU 纹理、实际提交和 SSE 同时达标。

Native 粗化和分区拟合的中间切面仍可能只有不达标的根需求。后台继续拟合这类切面，完成前保留已发布的可用测量需求，不发布会取消该需求的临时根计划。状态仍为未完成，相机通知仍在分片间生效；不存在的可用需求仍由原有根覆盖补齐。

相机停稳后，地形帧更新还曾将尚未收到新影像规划的切面暂时退回根需求。45 秒区域停顿中记录到 140 次正在执行的请求取消和 451 次排队取消；后台已完成多轮 Native 规划，下载却被反复打断。现在同一相机、Worker 世代、图源及规划参数下，按不可变模型资源将上一份有效影像需求接续到新地形帧。仍适用的金字塔下载不重新开始；退休模型过滤，新模型补根覆盖并阻止完整精度声明。相机预览变化、DPR、图源和 Worker 世代改变均不复用旧需求，部分计划可接续但不会变成完整计划。定向回归直接检查未完成下载的任务身份及新增、退休模型状态。

## 2026-10-09：持久显示切面、局部分组过渡与后台持续规划

本轮保留 Native 屏幕误差规划器与持久纹理金字塔，新增独立的 `ImageryPresentation` 显示管理器。Native 给出目标切面，`TextureStore` 根据下载、GPU 上传和可见兄弟块分区是否齐备生成候选切面，只有实际绘制才更新显示切面。显示状态以世界纹理单元保存，不依赖 terrain mesh ID 或相机版本；图源更换清空该状态，避免同名瓦片沿用旧图源内容。继承 nav3d/viewer 的父级完整覆盖、可见子组齐备和资源引用保护机制；保留 SDK 的独立影像 SSE，不照搬桌面纹理与地形层级绑定关系，也不把新增的定时渐变描述成桌面已有实现。

同一几何分片使用两套 UV 与两个纹理采样器，默认 200ms 线性过渡。稳定显示只执行一次纹理采样。粗化时保持旧细瓦片的空间分区，分别把每个细瓦片与其共同粗祖先混合，完成后才合并分区；不会将一张子瓦片拉伸覆盖整个父区域。推进可复用缓存中的精细候选；同一可见兄弟组须同时满足纹理和分区就绪，跨几何片段共同开始。往返缩放可沿同一对纹理的当前比例反向推进；第三个目标不会扩展采样器或排队链，当前一对结束后采用届时最新候选。

两端纹理直到替代内容提交前一直受缓存保护，沿用现有 CPU/GPU 资源计账、上传时限及分区预算。满缓存时使用已经驻留的粗祖先完成局部渐变以释放精细纹理名额，保留精度需求；不依赖先下载一个无法入缓存的替代者来解除旧资源保护。离开显示切面的单元自动退出，未提交的下载结果不能直接替换画面。质量统计按仍参与显示的较粗一端计算，过渡未结束时不能报告 ready、settled 或 quiescent。
