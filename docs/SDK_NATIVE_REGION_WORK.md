# 原生区域压缩任务

2026-10-19：`Terra::frame`新增`region_compaction_work`，作为
[同侧测量生产方案](SDK_FUSED_MEASUREMENT_PLAN.md)的第一个正式C++工作单元。
它处理调用方已提供的区域，不读取CBDAM、不执行投影，也尚未接入Web运行时。
目前Web继续使用已验收的JS压缩器；不能将本组件的合同通过解释为交互提速。

## 输入和数学合同

公开头为`terra/frame/region_compaction.hpp`。`measurement_region`包含原有
`imagery_region`、字段存在标记和调用方域编号。存在标记将缺失投影与全零投影
区分开；原样保留的区域保持域编号，新生成的归并三角形没有原块来源。

输入是`measurement_region_view`，包含语义行、固定数量及可选共享所有者。
调用方必须保持元素和存储不变并承担实际容量；提供所有者时任务持有它直到取消
或销毁，无所有者时调用方必须保证存储活到任务结束。此处没有隐式输入复制或
全局缓存。它替换了首版vector专用输入，供原生生产任务逐行构造后直接读取，
见[CBDAM精确面的原生生产边界](SDK_NATIVE_SURFACE_PROJECTION.md)。

算法保留旧JS实现的首个重复成员、稳定组序、局部密度和面积归并规则，不量化
坐标。支撑点提供的保守面积下界仅排除必定不能合并的组，其余照常求凸包。
密度允许正无穷；无效坐标、投影、NaN密度和非法标记被拒绝。中间计算的NaN
传播及正负零语义与旧数学合同保持一致，不能用忽略NaN的min/max放宽归并。

## 推进和准入

```text
validating → waiting_for_capacity → running → complete
    │                  │               │
    └────────────── cancelled ──────────┘
```

非法输入、分配失败和内部错误分别返回终态；取消可以结束任意阶段。没有投影
区域时，验证后直接完成，无需工作区。任务及共享预算属于同一个执行器，不支持
并发调用`step/read/cancel`。

`step(maximum_operations, maximum_milliseconds)`持久保存扫描、哈希探测、
稳定归并排序、点去重、凸包、面积及输出游标。每个变长循环的动作都计入操作数；
正时间窗口每64个内部动作检查一次，零时间窗口仅使用操作数。检查点留在原生
调用内部，不为每64个动作跨ABI传输一批区域。它提供协作式让出，不承诺分配器、
平台时钟或操作系统调度的硬截止时间。

验证结束后报告精确`required_work_bytes`。`step`在等待时不自动申请额度；
调用方收到容量变化后显式`admit()`。`work_bytes(input_count, projective_count)`
不分配内存，允许上游在生产原始区域前将输入和压缩工作区一起预留。

上游已预留时，使用`admit(credit&)`转移额度。它只接受同一预算、大小恰好匹配
的工作额度，拒绝驻留额度、其他预算和大小不匹配的额度。拒绝或实际分配失败
都保持上游额度原样，成功后额度只由任务持有，避免双重预留。

## 存储和释放

一次准入只进行一次精确定价的分配，包含私有持久状态、哈希表、数值暂存、排序
暂存、凸包和输出描述符。输出描述符引用输入点，不分配整幅物化结果。
`allocated_bytes()`反映该工作区。外层任务对象、输入、共享所有者控制块和
调用方输出不在这份工作区报价内，不能将其当成整个进程或完整测量链路预算。

完成后通过`read(first, output, capacity, count)`读取最多256行。输出元素
由调用方预先构造和计费；任务只复制或物化独立值，不返回内部内存视图。
等待、未完成、已取消或非法范围的读取不写元素。不在组件内部增加wire页。

`cancel()`先销毁状态和真实工作区，再归还工作额度，最后释放输入借用；重复
取消安全。取消一个任务不会退款同一预算里的其他工作或旧显示资源。完成本身
不自动释放描述符，调用方消费结束后仍须取消或销毁任务。

## 独立验证

`testdata/miniprogram/golden/region_compaction_v1.bin`保存23组旧JS输出，
覆盖空输入、标量、重复、乱序、空洞、密度变化、小组、极小面积输出扩张、坐标
平移、正负零、零深度/跨零深度及谱计算溢出。校验脚本检查冻结数据、生成器及
旧参考源的指纹，常规门控不重新计算数值真值。

- Native以1/7/64/4096动作推进，共92组对照；检查输出顺序、存在性、来源、
  数值、单次真实分配、少一字节拒绝、预留转移、分配失败、交错任务和释放次序。
- 隔离Wasm32构建以1/64/4096动作推进，共69组对照；补充内存增长、实际字节
  报价、有界读取、合成单调时钟和最终零句柄/零裸缓冲。
- ASan/UBSan专项针对同一生产核心及冻结输入检查越界、生命周期和未定义行为。

Native合同进入`verify_miniprogram_sdk.sh`，隔离Wasm合同进入
`verify_miniprogram_wasm.sh`。后者的`test_region_*`导出只属于测试构建，不
进入产品Wasm。当前不改变C ABI43和Worker41。

## 后续接入

已选精确面的真实CBDAM驻留loan、冻结候选读取及可续作count/fill投影已在
后续生产单元实现。整段测量仍需完整块模型、浅视块保守上界、完整身份与报价、
规范原生输入、宿主紧凑镜像及跨线程授权/释放回执。届时应直接消费本组件
描述符，避免重新生成每行JS对象再打包。
受限容量的地形/UV/影像联合发布、20秒停顿根因、实际帧时延、步行坡面和外部
设备验收仍按P0–P4原范围推进。本组件不改变CBDAM、八根纹理模型、误差或容量。

构建、发布、本机部署和清理结果分别记录，不由专项成功推定全门控通过。
