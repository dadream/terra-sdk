## 被否定的边界

候选将投影、六面裁剪、UV插值、面向与谱密度移入C++，每批最多64面；
ABI44提供原子批次，28600字节串行缓冲由现有input授权/回执管理。它满足
质量和基本生命周期合同，但仍逐面执行以下往返：

```text
JS/借用几何 → 打包坐标和UV → Wasm计算
            → 逐面读取投影系数与多边形 → JS扇形区域与压缩
            → 再打包 → Native影像规划器
```

在多数浅视区，SDK只需要聚合密度和包围范围，候选仍产生完整逐面结果；
在精确裁剪区，纯计算较快，但JS对象重建抵消了收益。逐面边界还没有消除
区域压缩、重复元数据和生产输入的二次转换。因此不继续通过扩大批次、降低
精度、放宽期限或删除联合准入保护来推动此候选。

桌面`ratman/ratman/src/vic/cbdam/base/texture_refiner.cpp`的纹理误差依据已达
CBDAM层级和可见性。SDK保留独立屏幕像素误差要求；不能把桌面的选级策略
直接复制为同等质量证明。值得保留的是原生模型上的持久工作、明确持有者和
有限拓扑变化，不是强制每个SDK三角面跨边界往返。

## 下一实现的必要边界

以一个不可变地形资源或未提交地形计划、一个投影代次为工作单元，在原生侧
连续完成投影、保守区域归并和现有影像输入生产；JS只接收紧凑、不可变的
可见需求与显示输出。先完成下面的所有权和可行性设计，再写生产代码。

1. **输入身份。** 明确数据集、图源、相机/视口、模型代次、资源ID或候选
   planId。相机变化只使投影需求过期；不销毁兼容的地形或已下载图像。
   不能仅比较某个计数器就复用来自另一网格或另一图源的结果。
2. **同时支持驻留与未提交几何。** `borrowed_mesh.js`能借用已驻留Wasm
   顶点；`prepared_surface.js`的候选仍有分段生成并复制到宿主的路径。
   新阶段必须能从对应原生计划有界读取，不能假设所有模型都有稳定指针，也
   不能为了测量先强制物化全部候选，绕过既有地形生产额度。
3. **单一测量持有者。** 用一个有预算的测量句柄持有区域，直接交给现有
   Native imagery input；保留`ImageryPlanner`的不可变输入复用。凡主线程
   当前画质、局部UV拟合或可见性确实需要的证据，必须定义紧凑输出与代次，
   不能删除这些证据后仍报告目标已达到。
4. **明确准入和退役。** 计算输入、区域输出、排序/归并暂存、Worker传输与
   宿主副本均须在生产前定价。每步具有持久游标、取消点和最大临时空间。
   额度不足保留当前显示并返回等待原因；真实停止后才退款。新的缓存不能
   再成为未计费的全局WeakMap或第二套几何持有者。
5. **完整质量证明。** 裁剪、面向容差、谱密度、无空UV填充的归并条件及
   节点局部SSE继续独立对照；浅视区可只输出摘要，精确区必须保留足以证明
   误差的区域。相机暂未测量的新区域仍保守处理。
6. **接入条件先于大场景重测。** 用固定网格、相机和输入量，比较完整生产
   路径的时间、跨边界字节、输出数量与实际存活内存；包含驻留、候选、取消、
   拒绝和内存增长。通过后再运行原质量、原期限的Worker/Direct、故障/普通
   网络轨迹，以及完整发布门控。单次采样或单一场景通过不足以发布。

受限容量的地形/UV/影像联合交接、完整派生元数据预算、20秒CDP/page停顿根因、
目标硬件帧率与输入延迟、徒步场景及其余P0–P4任务继续保持未完成。512KiB
仍只是体积参考；本次问题不是通过改变包体积门槛解决的。
