# 候选影像报价的持有边界

本增量修复P1联合准入中的一个实际所有权缺口。整体实施次序和性能证据见
[地形与影像准备链路](SDK_MEASUREMENT_PIPELINE.md)；完整P0–P4仍未完成。

## 触发条件

候选地形的影像报价会扣除已经缓存或已经预留的图片空间。例如四张子图已有
生产预留，报价可以是零新增字节。在等待新地形的UV报价时，当前视角仍可粗化
或移动。旧实现虽然通过`candidateDemands`禁止回收候选缓存图片，却没有把
候选借用的在途请求纳入`wantedKeys`及`isWanted`。

因此请求可以被视角裁剪取消，其预留在停止生产后释放；候选的`valid`却只检查
图源代数和是否关闭，仍返回有效。把取消后的请求当作已付费图片，可能让几何
准入与实际影像续作额度脱节。该缺口可以解释部分反复交互中的回退和额外等待，
尚无证据表明它独自解释已测得的整段斜视慢收敛。

## 实现

`sdk/js/resources/resource_cache.js`提供`borrowBatch`，集中管理一组已经付费的
缓存或在途目的地。它不分配图片，不启动生产，也不重复计费。

缓存借用检查实际条目身份。在途借用检查预留身份及尺寸；完成后自动转为对应
缓存条目的借用，取消、同键替换或改价会使原报价失效。部分借用失败及释放时
清理所有独立持有者，重复释放不重复退款。已有几何`reserveBatch`使用同一套
借用规则，消除两份所有权实现。

`adapters/webgl/texture_store.js`的`reserveCandidateDemand`同时持有这些借用和
缺失组的续作额度。候选必须在实际接纳前检查图片及UV凭据；接纳后由现有
需求保护接手，再释放临时借用。失败释放两类所有权；已经运行的原图片生产者
仍凭自己的停止回执释放空间，候选放弃不能提前退款。

请求裁剪只保留候选已经借用的在途键，不把整个未来纹理目标变成新的请求需求。
`produced_texture_store.js`中的分组预留裁剪使用同一持有集合，避免撤销已预留、
尚未开始的候选组成员。不存在的新图仍按原有完整组准入生产。
暂停、换源和销毁保持原有取消边界。
图像尺寸变化需要按实际大小重新报价，不能沿用旧尺寸的借用证明。

## 固定预算合同

`tests/js/candidate_image_ownership_contract.js`直接调用实际渲染器候选准入、资源
缓存、请求调度器和UV报价接口。只替换外部生产及GL设备，不使用网络或时间
重试来制造竞争。

| 一次完整局部交接的拥有者 | 字节 |
| --- | ---: |
| 旧几何与根覆盖 | 64 |
| 生产中的Native/host输入 | 60 |
| 四张图片的已有目的地或续作额度 | 16 |
| 新GPU几何 | 60 |
| 完整UV输入与GPU输出 | 48 |
| 合计 | 248 |

这些数值是受控生产者的报价与显式账本载荷，用于检验准入及退款关系，不是
实际CBDAM网格、Native工作区和裁剪输出的最小物理容量测量。

248字节下应同时保留旧覆盖并取得全部新组目的地，竞争者再申请1字节必须失败；
247字节下应拒绝且保留旧显示。另一分支只预留三张图，接纳后用已取得的4字节
额度生产第四张，总额不增加。实际请求调度器在视角变粗时不能取消正在被候选
借用的请求。取消、同键替换、尺寸变化、暂停和换源分别验证拒绝及零资源退出。

冻结旧`TextureStore`、保持相同测试及预算的三个负对照分别复现请求裁剪取消、
预留取消后报价仍有效、同键新预留掩盖旧预留丢失。既有几何、图片生产和Wasm
合同继续验证原有固定目的地规则。

第四个负对照冻结旧`ProducedTextureStore`，保留已修正的候选图片持有，独立
复现分组裁剪撤销候选组成员，防止只修网络请求而遗漏其已付费目的地。

该合同只证明这一局部准入及生命周期，不代表已验证真实GPU像素连续性、完整
CBDAM边界组在最低容量下持续发布，或二十余秒慢路径已经解决。硬件浏览器
轨迹和完整发布门控另行记录，不用单元合同代替应用验收。
